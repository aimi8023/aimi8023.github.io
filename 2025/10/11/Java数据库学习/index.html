Java数据库连接(从JDBC->Mybatis->SpringBoot)

Java 无Springboot数据库连接

学习 Java 数据库访问时，经常会遇到 JDBC、数据源、MyBatis 和 Spring Boot 等概念。本文从它们之间的关系出发，逐步梳理各层技术解决的问题。

1 JDBC和数据库驱动的关系

  • JDBC是什么？

JDBC全称为 Java DataBase Connectivity(Java 数据库连接)，是Java官方提供的连接数据库的API规范，它是一个API 接口，内部定义了连接数据库的接口和方法。但需要注意：仅仅只是定义了接口和方法，并没有实现这些接口和方法。

	比如：
函数名 功能 由谁定义 由谁实现
Drivermanager.getConnection() 数据库连接 Java官方 数据库厂商（如Mysql、Oracle等官方）
Connection.createStatement() Sql语言执行器 Java官方 数据库厂商（如Mysql、Oracle等官方）
Statement.executeQuery() 查询方法 Java官方 数据库厂商（如Mysql、Oracle等官方）
Statement.getResultSet(); 得到结果集 Java官方 数据库厂商（如Mysql、Oracle等官方）
······· ······· Java官方 数据库厂商（如Mysql、Oracle等官方）

上述方法都是由Java官方定义好接口和方法，具体实现由各家数据库厂商去分别针对自家的数据库去实现，数据库厂家提供的JDBC具体实现就是数据库驱动。

		因此，在Java里想要连接数据库，必须先引入对应的数据库驱动。想要使用Mysql就需要引入`mysql-connector-j`依赖，想要使用Oracle就需要引入`ojdbc8`依赖,想要使用SQLite就需要引入`sqlite-jdbc`依赖。作为Java程序员，只需要学习Java定义好的JDBC方法，就能操纵不同的数据库，只需要更换不同的数据库依赖即可。

2 数据源(DataSource) 是什么？有什么作用？

既然依靠JDBC和数据库驱动就能操纵数据库，那么数据源DataSource又是什么呢？实际上，DataSource也是JDBC，不过是对JDBC内部获取数据库连接这个特定功能的升级版。

		无论操纵什么数据库，我们首先都需要获取一个数据库连接，传统方式采用`DriverManager`,现在主流使用`DataSource`方式连接数据库，两者有什么区别呢？

DriverManager:

  • 这是一个静态类，由Java官方提供，不需要数据库厂商或第三方实现。

  • 获取连接方式：每次调用DriverManager.getConnection(url,user,password)都会新建一个数据库连接。

  • 连接池：没有连接池，每次操作都需要新建和关闭连接，性能较低。

  • 没有SQL 监控，没有异常统计，配置内嵌入代码，不易维护。

DataSource:

  • 这是一个接口，由Java官方定义但不实现，需要数据库厂商或第三方实现。

  • 获取连接方式：通过dataSource.getConnection()获取数据库连接,连接可复用。

  • 连接池：通常自带连接池，性能高。

  • 有SQL 监控，有异常统计，配置可结合Spring外置，方便维护。

3 Mybatis 对JDBC的再封装

Mybatis 介绍

官网：MyBatis 官方介绍

接下来是Mybatis的出现，它是做什么的呢？直接使用JDBC我们也发现了，需要配置数据源->获取数据库连接->Sql语句执行->获取结果集，而且还要在java代码中写sql语句，这实际上非常不符合应用开发的解耦性；因此，Mybatis对JDBC进行了再封装，让我们在写java代码时只关注Java，写sql语言时就只是写Sql（:fearful:虽然我感觉也并不简便）。但要明白：Mybatis只是对Jdbc的再封装，实际上底层依然是调用JDBC的接口操纵数据库。

	由于单纯的`Mybatis 不结合Springboot`过于麻烦，因此这里只做简单讲解。下文结合Springboot的Mybatis使用简便不少而且常用。

最后的这一部分是重点，MyBatis 操作数据库的关键就在这里。请重点理解 SqlSessionFactoryBuilder、SqlSessionFactory、SqlSession 以及 UserMapper。

  • SqlSessionFactoryBuilder

    • 作用：用于创建SqlSessionFactory，通过读取Mybatis-config.xml的输入流
    • 生命周期：一旦创建好SqlSessionFactory,就不再需要它
    • 比喻：SqlSession的生产工厂的建筑工人，工厂建好即可抛弃

  • SqlSessionFactory

    • 作用：用于生产(创建)SqlSession,通过sqlSessionFactory.openSession()
    • 生命周期: 应用程序运行期间一直存在且唯一，没有理由抛弃或创建第二个。
    • 比喻：SqlSession的建造工厂，专用于生产一个个SqlSession

  • SqlSession

    • 作用：Session意思为会话，SqlSession即表示数据库会话对象
    • 生命周期：在一个进程或一个方法内使用，不能跨进程使用
    • 比喻：数据库的操作员工，用来增删改查的真正对象

  • UserMapper userMapper = sqlSession.getMapper(UserMapper.class)

    • 最重要的一行代码，表面看我们得到了一个接口对象，实际上内部是动态代理对象
调用过程如下
当调用sqlSession.getMapper(UserMapper.class)；
↓ (调用)
this.configuration.getMapper(type, this) 其中this 即当前sqlSession对象，type即UserMapper.class 类型
↓(调用)
this.mapperRegistry.getMapper(type, sqlSession) 其中this 即当前sqlSession.configuration对象，sqlSession即当前sqlSession 对象
↓(调用)
mapperProxyFactory.newInstance(sqlSession) 其中type在这一步已经被确定，不需要往下传了；只需要通过sqlSession得到代理对象
↓(调用)
Proxy.newProxyInstance(this.mapperInterface.getClassLoader(), `` new Class[]{this.mapperInterface}, `` mapperProxy) 到这一步可以清晰发现它是利用了动态代理的方式去生成Mapper的代理对象，而非Mapper的实现类
  • 因此,UserMapper的每一个方法的调用都会被代理对象拦截，因为它本身就是动态代理对象。

进一步Druid配置

		使用Druid真的只有这么简单吗？如果只是添加type这一项配置的话，实际上无法满足更深层次的需求，比如使用Druid数据源的独有方法，配置它的连接，监控和安全等功能，所以我们需要**注册一个DruidDataSource的bean**。

步骤：

  1. 创建配置类DruidSourceConfig,名字和位置其实并不重要，但推荐规范，便于开发维护。

  2. 为类添加注解@Configuration，作用是Spring会在启动时扫描它并为其里面的@Bean方法注册并托管.

  3. 创建方法public DruidDataSource druidDataSource(),这个方法的名字其实随便，但是返回值一定是DruidDataSource,spring自动注入依靠的就是这个返回值类型。

  4. 为这个方法添加三个注解。

    • @Bean

      告诉 Spring，方法返回的对象要被注册为一个 Bean，并由 Spring 容器管理

    • @ConfigurationProperties(prefix = “spring.datasource”)

      把 application.yml 中，以 spring.datasource 开头的配置，自动绑定到这个 Bean 的属性上。

    • @ConditionalOnProperty(name = “spring.datasource.type”, havingValue = “com.alibaba.druid.pool.DruidDataSource”)

      为避免和默认 Hikari 或其他数据源冲突，只有当配置文件中存在 spring.datasource.type=com.alibaba.druid.pool.DruidDataSource 时，这个 Bean 才会被创建。

三 Springboot —Mybatis的使用

	Mybatis的使用也需要从导入依赖开始。

导入Mybatis依赖

MyBatis 有多种适配不同环境的依赖：

  • mybatis：只使用 MyBatis 核心功能，不依赖 Spring 框架。
  • mybatis-spring：用于 Spring 项目，但不是 Spring Boot 项目。
  • mybatis-spring-boot-starter：MyBatis 与 Spring Boot 的整合启动器。

配置

	mybatis的spring配置很简单，没什么别的需求的话只需要添加自动扫描*.xml和为实体类起别名;但是请特别注意几个文件的位置。
