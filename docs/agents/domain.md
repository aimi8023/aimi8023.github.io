# 领域文档

工程技能在探索代码库时，按照以下规则消费本仓库的领域文档。

## 探索前阅读

- **`CONTEXT.md`**（仓库根目录下的项目上下文文件）
- **`docs/adr/`**——在即将工作的区域范围内阅读相关 ADR。

若上述文件不存在，**静默跳过**。不要主动标记缺失，也不要建议立即创建。`/domain-modeling` 技能（通过 `/grill-with-docs` 和 `/improve-codebase-architecture` 调用）会在真正解析到术语或决策时惰性创建它们。

## 文件结构

单一上下文仓库（本项目）：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── source/
```

## 使用术语表中的词汇

当输出中命名领域概念时，使用 `CONTEXT.md` 中定义的术语。不要偏离到词汇表明确排除的同义词。

如果需要使用的概念尚未纳入词汇表，这是一个信号——要么你在创造项目未使用的语言（重新考虑），要么确实存在空白（记录下来供 `/domain-modeling` 处理）。

## 标记 ADR 冲突

若你的输出与现有 ADR 矛盾，明确将其表面化，而不是默默覆盖：

> _与 ADR-0007（xxx）矛盾——但值得重新审视，因为……_
